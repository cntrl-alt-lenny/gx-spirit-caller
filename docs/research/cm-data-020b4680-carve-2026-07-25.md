# cm-data-020b4680-carve: splitting the evidenced prefix from an unevidenced tail (2026-07-25)

Executes the second deferred finding from `cm-data-inference-3`:
`data_020b4680` (96 bytes, opaque `const unsigned char[96]`) has
strong, exhaustive consumer evidence for only its first 32 bytes.
Unlike `cm-data-020c3198-carve` (a mid-record dsd split, several
symbols already existing at sub-offsets of one physical table), this
is a **clean prefix/tail split at a record boundary** — simpler in
shape, no toolchain-alias questions, no dsd gap-filler involved.

## The evidence

Both known consumers, `func_02002c3c.s` and `func_02002ffc.s` (grepped
the whole `src/` tree for `data_020b4680` — confirmed no third
consumer exists), extract a nibble from a packed byte and mask it
`& 0xf` before an `lsl #1` halfword-stride load:

```
and r6, r7, #0xf0
mov r6, r6, asr #0x4
and r6, r6, #0xff      ; nibble, guaranteed [0,15]
mov r8, r6, lsl #0x1   ; idx*2 byte stride
ldr r6, _LIT4           ; &data_020b4680
ldrh r6, [r6, r8]
```

The mask is unconditional and precedes every load — this is a
hardware-enforced bound, not an inferred one. `table[n]` spreads the 4
bits of `n` into 4 nibble lanes (`table[5] = table[0b0101] = 0x0101`,
`table[11] = table[0b1011] = 0x1101`), confirmed by decoding all 16
values from the existing bytes before writing any code. Both
consumers repeat this pattern multiple times per call (unpacking
several nibbles from different source bytes), always against the same
16-entry table, never with a wider mask.

The remaining 64 bytes (offset 0x20–0x5F) are structurally
unreachable by either consumer's masked index — not just
"unreferenced in the functions we happened to check," but impossible
to reach given the `& 0xf` bound. Zero shape evidence for this tail.

## The fix

1. Confirmed no `size=` is specified on sibling `kind:data(any)`
   symbols.txt entries in this neighborhood (`data_020b4680`,
   `data_020b46e0`) — the new `data_020b46a0` entry matches that
   convention, no size added.
2. Split `src/main/data_020b4680.c` into two files at the byte-32
   boundary:
   - `data_020b4680.c`: `const unsigned short data_020b4680[16]`, the
     evidenced nibble-spread table.
   - `data_020b46a0.c` (new symbol, new file): `const unsigned char
     data_020b46a0[64]`, still opaque — no shape forced onto
     unevidenced bytes.
3. `delinks.txt`: replaced the single `0x020b4680`–`0x020b46e0` entry
   with two contiguous entries at the `0x020b46a0` boundary.
   `batch_carve.py`'s own `audit()` reports 0 problems.
4. `symbols.txt`: added one new entry, `data_020b46a0 kind:data(any)
   addr:0x020b46a0`, in address-sorted position next to its neighbors.

## Verification

- **Byte-for-byte, not just "compiles clean":** the original 96-byte
  literal (from `origin/main`, before this split) compared
  programmatically against the concatenation of both new objects'
  compiled `.rodata` sections (`objdump -s -j .rodata`) — exact match
  across all 96 bytes.
- **Full 3-region gate**, run twice: the first run hit a real but
  self-inflicted `ninja: error: loading 'build.ninja': ... being used
  by another process` on `usa` — caused by an earlier manual `&`-
  backgrounded gate run from the same session whose process outlived
  the shell check that reported it as finished (Bash tool shell state
  does not persist between calls the way a single long-lived terminal
  would). Confirmed no stray `python`/`ninja` processes remained
  (`tasklist`), re-ran cleanly: `python tools/gate3.py --scope all` →
  `GATE PASS`, all three of `[eur] SHA1 PASS` / `[usa] SHA1 PASS` /
  `[jpn] SHA1 PASS` grepped individually from the log (not assumed
  from the final banner alone), `pytest`: 3017 passed, 16 skipped, 0
  failed.

## Field semantics (not required for byte-correctness, noted for future readers)

The evidenced table is unambiguous: a 4-bit-to-4-nibble spread,
probably used to expand a compact per-object flag nibble into a
per-lane byte-addressable form for some downstream bit-test loop. The
64-byte tail's shape remains completely unknown — a genuine candidate
for a future wave if a currently-uninvestigated consumer turns up.
